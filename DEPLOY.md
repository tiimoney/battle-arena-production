# Deploying Mocheso League

Single combined deployment: one Node process serves both the API and the built React
app from the same origin, so there's no cross-site cookie configuration to worry
about. The repo lives on GitHub; [Render](https://render.com) auto-deploys from it on
every push using the `render.yaml` blueprint at the repo root.

## One-time setup

1. **Push this repo to GitHub** (see the commands in the PR/commit that added this
   file, or just `git remote add origin <your-repo-url> && git push -u origin main`).
2. **Create a Render Blueprint**: on [dashboard.render.com](https://dashboard.render.com),
   click **New +** → **Blueprint**, connect your GitHub account, and pick this repo.
   Render reads `render.yaml` and provisions a single free web service from it.
3. Render will prompt you for the env vars marked `sync: false` in `render.yaml`:
   - `DATABASE_URL` — your Neon **pooled** connection string.
   - `DIRECT_URL` — your Neon **unpooled** connection string (migrations need this).
   - `RESEND_API_KEY` — optional; leave blank and verification emails just log to the
     Render service's logs instead of sending, until you add a real key.
   - `EMAIL_FROM` — pre-filled with Resend's shared sandbox address; only deliverable
     to your own Resend account until you verify a real sending domain.
   - `JWT_SECRET` is auto-generated by Render — you don't need to set it.
4. Deploy. Render runs `npm install && npm run build && npx prisma migrate deploy`
   (applying any pending schema migrations against `DIRECT_URL`), then starts the
   server, which serves the API and the built client from the same URL Render gives
   you (`https://<service-name>.onrender.com`).

## After that

Every `git push` to the branch Render is watching triggers a new build + deploy
automatically — that's the whole "GitHub hosting" loop: GitHub is the source of
truth, Render is what actually runs it.

Free-tier notes: Render's free web service spins down after 15 minutes of no
traffic and takes a few seconds to wake back up on the next request; Neon's free
compute similarly scales to zero when idle. Neither affects correctness, just
first-request latency after a quiet spell.

## Custom domain (optional)

Render's free tier supports attaching your own domain to the service for no extra
cost (just DNS you control) — Settings → Custom Domains on the service in the Render
dashboard.
